CanvasCore — คู่มือใช้งาน

เอกสารนี้สอนวิธีใช้แพ็คเกจนี้ในโปรเจ็คของคุณ ตั้งแต่ setup ครั้งแรกไปจนถึงการสร้างหน้าจอ/popup/list ยาวๆ ของตัวเอง — ถ้าอยากรู้ เหตุผล เบื้องหลังการออกแบบแต่ละจุด ดูที่ CanvasCore-Docs.html ที่ root ของโปรเจ็คแทน

เริ่มต้นใช้งาน

  1. ลาก UIRoot.prefab ลง Scene

    อยู่ที่ Prefabs/UIRoot.prefab — เป็น root Canvas พร้อม 6 Layer (Background/Screen/Popup/Overlay/Toast/Blocker) สำเร็จรูป ไม่ต้องประกอบ Canvas เอง

  2. เพิ่ม UIBootstrap component ลง GameObject ไหนก็ได้ในซีน

    ลาก UIRoot.prefab เข้าช่อง Root Prefab และลาก catalog asset ของคุณ (ดูข้อ 3) เข้าช่อง Catalog — UIBootstrap.Awake() จะ instantiate root + สร้าง UIManager ให้อัตโนมัติตอนเข้า Play

  3. สร้าง UICatalogSO asset ของโปรเจ็คตัวเอง

    คลิกขวาใน Project window → Create > Aexxa > CanvasCore > UI Catalog (ถ้าหาไม่เจอ พิมพ์ "UICatalog" ในช่องค้นหา Create menu) — เก็บไว้ที่ไหนในโปรเจ็คก็ได้ ไม่จำเป็นต้องอยู่ใต้ Plugins/aexxa/

  4. เขียน UI class แรกของคุณ

    สืบทอด UIScreen/UIPopup/UIWidget ตามด้านแนวคิดหลัก แล้ว build prefab คู่กัน วางไว้ใต้โฟลเดอร์ที่ชื่อ Resources เป๊ะ (ดูเหตุผลในCatalog Inspector)

  5. เปิด catalog asset → กด "Scan Resources/UI"

    ระบบจะหา prefab ที่มี UIView component ทุกตัวใต้โฟลเดอร์ Resources แล้วเพิ่ม entry ให้เอง พร้อมเดา layer และตั้งค่า pool ที่เหมาะสมให้ทันที

  6. เรียกจากโค้ดเกม

    UIManager.Instance.Show<SettingsScreen>();

    เท่านี้จบ — ดูตัวอย่างที่รันได้จริงทั้งหมดใน Examples/ (ลบทิ้งได้เมื่อพร้อมเริ่มสร้าง UI ของตัวเอง)

แนวคิดหลัก

isStacked = true แปลว่าเปิดตัวใหม่แล้วตัวก่อนหน้าใน layer เดียวกันจะถูกซ่อนอัตโนมัติ (ไม่ได้ despawn) — ปิดตัวบนสุดแล้วตัวที่ซ่อนไว้จะโชว์กลับมาเอง เหมาะกับ Screen/Popup ที่นำทางเป็นลำดับ

เลือก base class ให้ถูก

UIScreen

ใช้กับ Show<T>() / Hide<T>() — instance เดียวต่อ Type เท่านั้น layer เป็น isStacked = true เข้าคิว back-stack ให้อัตโนมัติ ติ๊ก Is Root Screen ใน Inspector สำหรับจอที่เป็นฐานของ navigation (HUD/MainMenu) เพื่อกัน HandleBack() ปิดจอนี้ทิ้ง

UIPopup

ใช้ Show<T>() / Hide<T>() เหมือนเดิม แต่มีคิวในตัว: มีได้แค่ 1 popup บนจอพร้อมกันเสมอ ไม่ว่าจะเป็น type เดียวกันหรือคนละ type ถ้าเรียก Show ตอนที่มี popup อื่นเปิดอยู่ คำขอนั้นจะเข้าคิวรอแทนที่จะไปทับ/แย่งของเดิม แล้วโชว์เองอัตโนมัติตามลำดับที่เปิดปิดจริง — ลาก Button ของ backdrop เข้าช่อง Backdrop Button แล้วได้คลิกนอกกรอบปิดฟรี ปลดติ๊ก Close On Backdrop Click ใน Inspector สำหรับ popup ที่ต้องการให้เลือกปุ่มเท่านั้น (เช่น confirm dialog)

UIWidget / UIToast

ใช้กับ Spawn<T>() / Despawn() — สร้างได้หลาย instance พร้อมกัน (floating damage text, toast ซ้อนกัน) UIToast เป็น UIWidget ที่ auto-dismiss ตัวเองตาม duration ให้แล้ว

UIBackground

ใช้กับ Show<T>() / Hide<T>() เหมือน UIScreen/UIPopup — instance เดียวต่อ Type แต่ layer เป็น isStacked = false จึงไม่เข้าคิว back-stack และไม่ตอบสนอง HandleBack() เหมาะกับของที่โชว์/ซ่อนแบบอิสระตลอดเกม (backdrop)

UIBlocker

เหมือน UIBackground (isStacked = false) แต่ Show<T>()/Hide<T>() นับ reference count ให้อัตโนมัติ — เรียก API เดียวกัน ไม่ต้องจำ method แยก — กัน 2 ระบบเรียก block พร้อมกันแล้วอันหนึ่งปล่อยก่อนจนอีกอันหลุด block ไปด้วย

ทั้ง 5 base class สืบทอดจาก UIView โดยตรง (ยกเว้น UIToast : UIWidget) — Catalog Inspector ใช้ type นี้เดา layer/pool defaults ให้อัตโนมัติตอนกด "Scan and add missing entries" ดังนั้นเลือก base class ให้ตรงกับ layer ที่ตั้งใจใช้จริงเสมอ

ทำไม prefab ต้องอยู่ใน Resources/

UICatalogEntry เก็บ prefab เป็น string resourcePath ไม่ใช่ direct reference — เพื่อไม่ให้ Unity โหลดทุก prefab ใน catalog เข้า RAM ตั้งแต่ scene เปิด (ผลข้างเคียงของกติกา eager-load ของ direct reference) prefab แต่ละตัวจะถูกโหลดจริงผ่าน Resources.Load ก็ต่อเมื่อ pool ของ Type นั้นถูกสร้างครั้งแรกเท่านั้น (ตอน prewarm หรือตอน Show/Spawn ครั้งแรก) — นี่คือเหตุผลที่ต้องวางไฟล์ไว้ใต้โฟลเดอร์ที่ชื่อ Resources เป๊ะ

Pooling

ทุก UIView ถูก pool ผ่าน UnityEngine.Pool.ObjectPool<T> อัตโนมัติ — implement IPoolable lifecycle 3 จุดถ้าต้องการ:

public override void OnCreated()   { /* ครั้งแรกที่ instantiate เท่านั้น — wire onClick ที่นี่ */ }
public override void OnSpawn(object context) { /* ทุกครั้งที่ Show/Spawn — รับค่าที่ส่งเข้ามา */ }
public override void OnDespawn()   { /* ทุกครั้งที่ Hide/Despawn — เคลียร์ state/callback ค้าง */ }

สร้าง UI ใหม่ — ตัวอย่างเต็ม

using Aexxa.CanvasCore;
using TMPro;
using UnityEngine;
using UnityEngine.UI;

public sealed class RewardPopup : UIPopup
{
    [SerializeField] private TMP_Text titleText;
    [SerializeField] private Button claimButton;

    public readonly struct Context
    {
        public readonly string Title;
        public Context(string title) => Title = title;
    }

    public override void OnCreated()
    {
        claimButton.onClick.AddListener(HandleClaim);
    }

    public override void OnSpawn(object context)
    {
        titleText.text = ((Context)context).Title;
    }

    private void HandleClaim()
    {
        UIManager.Instance.Hide<RewardPopup>();
    }
}

  1. Build prefab

    root ต้องมี CanvasGroup (component ที่ UIView ต้องการ) — สร้าง GameObject ว่างๆ แล้ว Add Component RewardPopup ได้เลย ระบบจะเติม CanvasGroup ให้ผ่าน Reset()

  2. วางไว้ใต้ Resources/UI/Popup/Reward/RewardPopup.prefab

    ตั้งชื่อโฟลเดอร์ตาม layer ก่อนแล้วค่อยตามชื่อ element เอง (ดูตัวอย่างจริงใน Examples/Resources/UI/)

  3. เปิด catalog → "Scan Resources/UI"

    หรือกด "+ Add Entry" แล้วลาก prefab เข้าช่อง "Drag prefab" กด "Sync" เอง

  4. เรียกใช้

    UIManager.Instance.Show<RewardPopup>(new RewardPopup.Context("ยินดีด้วย!"));

Catalog Inspector

เปิด UICatalogSO asset ขึ้นมาจะเห็น custom Inspector (ไม่ใช่ default array UI ของ Unity) — entry แต่ละอันจัดกลุ่มตาม Layer อัตโนมัติ (โชว์เฉพาะ layer ที่มี entry จริง) collapse เหลือบรรทัดเดียวโดย default

คำเตือน entry ซ้ำ

ถ้ามีสอง entry ชี้ไป Type เดียวกัน Inspector จะเตือนด้วย HelpBox สีเหลืองทันที — UIManager.Show<T>() จะ resolve ได้แค่ตัวเดียวเท่านั้น (ตัวไหนไม่แน่นอน) ต้องลบตัวซ้ำออก

RecycledScrollView — List ยาวๆ

list ปกติที่ instantiate 1 GameObject ต่อ 1 item จะพังเมื่อ item เยอะ (1000+) — RecycledScrollView instantiate cell แค่เท่าที่ viewport แสดงได้ (+ overscan buffer) แล้ว rebind ซ้ำตาม index ที่เลื่อนเข้ามา ไม่ว่าจะมีกี่ item

1. เขียน cell ที่ implement IRecycledScrollCell

using Aexxa.CanvasCore;
using TMPro;
using UnityEngine;

public sealed class ItemCell : MonoBehaviour, IRecycledScrollCell
{
    [SerializeField] private TMP_Text label;

    public void Bind(int index)
    {
        label.text = MyDataSource.Items[index].Name;
    }
}

2. Build cell prefab + scroll view

เร็วสุดคือลาก Prefabs/DesignSystem/ScrollView.prefab ลง Scene (มี ScrollRect/RecycledScrollView wire ไว้ครบแล้ว รอแค่ assign Cell Prefab) แล้วสร้าง cell prefab ของตัวเองแยกลาก assign เข้าช่อง Cell Prefab ใน Inspector — ปรับ Cell Size ให้ตรงความสูงจริงของ cell

3. เรียกใช้จากโค้ด

[SerializeField] private RecycledScrollView scrollView;

private void Start()
{
    scrollView.SetItemCount(MyDataSource.Items.Count);
}

// list เปลี่ยน (filter/sort/reload) — เรียกซ้ำได้เสมอ
private void OnFilterChanged() => scrollView.SetItemCount(MyDataSource.FilteredCount);

// ข้อมูลเปลี่ยนแต่จำนวน/ตำแหน่ง scroll เดิม — rebind เฉพาะที่เห็นอยู่ ไม่ reset scroll
private void OnDataMutated() => scrollView.Refresh();
ข้อควรระวัง: ถ้าเรียก SetItemCount() จาก OnCreated() ของ UIView (เช่นเดียวกับตัวอย่าง InventoryScreen) ระบบจะ force Canvas.ForceUpdateCanvases() ให้อัตโนมัติภายในเพื่อวัดขนาด viewport ให้แม่นตั้งแต่เฟรมแรก — ไม่ต้องกังวลเรื่อง pool เล็กเกินไปเพราะ layout ยังไม่ settle

ข้อจำกัด

  • รองรับแค่ vertical scroll, fixed cell height เท่ากันทุกอัน (v1)
  • ห้ามใส่ LayoutGroup/ContentSizeFitter บน Content — RecycledScrollView คุม anchor/size ของมันเองเต็มที่ ใส่ซ้อนจะแย่งกันคุม

GameObject > Canvas Core > Create

เมนูสร้าง element จาก prefab แบบคลิกเดียว เหมือน GameObject > UI > Button ของ Unity เอง — ต่างจาก catalog ตรงที่ไม่เกี่ยวกับ UIView/Show-Hide เลย ใช้สำหรับ element ย่อยที่อยาก drag ลง scene ซ้ำๆ ได้ง่าย (ปุ่ม, การ์ด, หรือ GameObject อะไรก็ได้)

  1. เปิด Resources/CanvasCoreSettings.asset

    ตั้งค่า "Prefab Folder" เป็นโฟลเดอร์ที่จะสแกน (default คือ Prefabs/DesignSystem/ ซึ่งมี Button.prefab/ScrollView.prefab เป็นตัวอย่างอยู่แล้ว) — ลากโฟลเดอร์เข้าไปตรงๆ เหมือนฟิลด์ "Default Style Sheet" ของ TMP Settings

  2. วาง prefab ที่ต้องการเข้าไปในโฟลเดอร์นั้น

    ชื่อ prefab อะไรก็ได้ ไม่มีข้อบังคับ — ชื่อ prefab จะกลายเป็น label ของเมนูตรงๆ

  3. กด "Scan & Generate Menu"

    หรือเมนู Tools > CanvasCore > Scan Create Menu Prefabs — เขียนไฟล์ [MenuItem] จริงให้ ไม่ใช่ popup/dropdown

  4. ใช้งาน

    คลิกขวาใน Hierarchy (หรือเมนู GameObject) → Canvas Core > Create > {ชื่อ prefab} — ถ้า context เป็น RectTransform จะ parent เข้าใต้นั้น ไม่งั้นหา/สร้าง Canvas ให้อัตโนมัติ

การสแกนเป็น action ที่ต้องสั่งเอง ไม่มี background watcher คอย regenerate อัตโนมัติทุกครั้งที่ไฟล์เปลี่ยน — กันไม่ให้ recompile กระตุกโดยไม่ทันตั้งตัวตอนแก้ prefab บ่อยๆ

Back Button / ESC และ Toast

Back Button

UIBootstrap ต่อสาย Escape/Android back button ให้อัตโนมัติ (ตรวจ Input System/Legacy Input Manager ให้เองตาม project settings) — ปิด view บนสุดของ stacked layer ที่ priority สูงสุด (Popup ก่อน Screen เสมอ) ปิด toggle Auto Handle Back Input บน UIBootstrap ถ้าอยากต่อสายเอง แล้วเรียกตรงๆ:

UIManager.Instance.HandleBack();

ถ้า view บนสุดเป็น UIScreen ที่ติ๊ก Is Root Screen ไว้ใน Inspector (เช่น HUD/MainMenu ที่ไม่มีอะไรอยู่ข้างใต้) HandleBack() จะไม่ปิดแล้วคืน false แทน — ให้โค้ดเกมเช็ค return value แล้วต่อ logic exit-confirm ของตัวเองได้ (ดูตัวอย่างจริงใน MainMenuScreen.prefab)

Toast

สืบทอด UIToast แทน UIWidget เฉยๆ — ได้ auto-dismiss ตาม duration ให้ฟรี ไม่ต้องเรียก Hide/Despawn เอง:

UIManager.Instance.Toast<SimpleToast>("บันทึกเรียบร้อย", duration: 2f);

Popup — คิวในตัว ไม่ทับกัน

Show<T>() ของ UIPopup มีคิวในตัว — เรียกได้จากหลายจุดในโค้ดพร้อมกัน (เช่น ระบบ error กับระบบ reward ทั้งคู่เรียก Show เกือบพร้อมกัน) โดยไม่ต้องกลัวว่าอันหลังจะไปทับ context ของอันแรกที่ผู้ใช้ยังไม่ได้ตอบ:

UIManager.Instance.Show<ConfirmPopup>(new ConfirmPopup.Context("ลบไฟล์?", "...", OnConfirmDelete, null));
// เรียกจากอีกจุดนึงเกือบพร้อมกัน — อันนี้เข้าคิว ไม่ไปแย่ง popup ด้านบนที่ยังค้างอยู่
UIManager.Instance.Show<ConfirmPopup>(new ConfirmPopup.Context("ออกจากเกม?", "...", OnConfirmQuit, null));

popup แรกปิด (ไม่ว่าจะกดปุ่ม, คลิก backdrop, หรือกด back) popup ที่สองจะโชว์เองอัตโนมัติตามลำดับที่เรียก — ใช้ API เดิม Show<T>() ทุกอย่าง ไม่มี method ใหม่ให้เรียก

ยกเลิก popup ที่ยังไม่ถึงคิว

popup ที่เข้าคิวรออยู่ (ยังไม่โชว์) ยกเลิกด้วย Hide<T>() ไม่ได้ — ตัวนั้นแก้ได้แค่ popup ที่กำลังโชว์อยู่บนจอเท่านั้น ใช้ 2 เมธอดนี้แทนสำหรับล้างคิว:

UIManager.Instance.CancelQueued<ConfirmPopup>();  // ล้างเฉพาะ type นี้ที่รอคิวอยู่
UIManager.Instance.ClearPopupQueue();               // ล้างทุก popup ที่รอคิว ไม่ว่า type ไหน

ทั้งคู่ไม่แตะ popup ที่กำลังโชว์อยู่บนจอ (ใช้ Hide<T>()/Close() สำหรับตัวนั้น) และปล่อย instance ที่ถูกยกเลิกกลับ pool ผ่าน OnDespawn() ตามปกติ — เรียก ClearPopupQueue() จากโค้ดจัดการ scene transition/reset state ของเกมเองตรงจุดที่ popup ที่ค้างคิวไม่มีความหมายแล้ว (เช่น ก่อนโหลด level ใหม่ กัน popup ของ level เก่าไปโผล่ใน level ใหม่)

ทั้งสองเมธอดนี้เป็นแค่เครื่องมือให้เรียกเอง (opt-in) — ไม่ได้ตรวจจับ reference เสียให้อัตโนมัติ popup ที่รอคิวอาจถูกถือ context ไว้นานแค่ไหนก็ได้ก่อนถึงตาโชว์จริง ถ้า context capture reference ของ object ใน scene (เช่น callback ที่เรียก method ของ enemy ตัวหนึ่ง) แล้ว object นั้นถูก destroy ไปโดยที่ไม่มีใครเรียก ClearPopupQueue()/CancelQueued<T>() popup นั้นจะยังโผล่ตามคิวปกติแล้ว callback จะพังตอนถูกเรียก — framework ตรวจจับกรณีนี้เองไม่ได้ (context เป็น object/Action ทั่วไป ไม่มีทางรู้ว่าข้างในอ้างถึงอะไรบ้าง) ดังนั้น:
  • clear reference ที่ capture ไว้ใน OnDespawn() เสมอ (ดูตัวอย่างใน ConfirmPopup.OnDespawn()) — ช่วยตอนถูกยกเลิกผ่าน 2 เมธอดด้านบน แต่ไม่ช่วยถ้า popup โผล่ขึ้นมาแสดงจริงพร้อม callback เสีย
  • เรียก ClearPopupQueue()/CancelQueued<T>() เชิงรุกตรงจุดที่รู้ว่า state ที่ popup อ้างถึงกำลังจะหายไป (scene unload, player death, object pool recycle ฯลฯ) — อย่ารอให้ popup ไปเจอเอง

จำกัดความยาวคิว

คิวไม่ยาวไม่จำกัด — UIManager constructor รับ maxQueuedPopups (default 20) ถ้าคิวเต็ม Show<T>() ครั้งถัดไปจะถูกตัดทิ้งทันที (ไม่โชว์ ไม่เข้าคิว ปล่อยกลับ pool ผ่าน OnDespawn() เหมือนถูกยกเลิก) พร้อม Debug.LogWarning บอกชื่อ type ที่โดนตัด — กันเคส bug จริง เช่น มีจุดไหนเผลอเรียก Show<Popup>() ในลูปหรือทุกเฟรมโดยไม่ได้ตั้งใจ ไม่ให้คิวบวมไม่จำกัด ค่า return ของ Show<T>() ยังเป็น instance จริงเสมอ (ไม่ใช่ null) ตาม contract เดิม แค่ไม่เคยถูกโชว์เท่านั้น

// ปรับ cap เองได้ตอนสร้าง UIManager (ปกติ UIBootstrap เป็นคนสร้างให้อยู่แล้วด้วยค่า default)
new UIManager(catalog, root, maxQueuedPopups: 50);

Popup — ปิดเมื่อคลิกนอกกรอบ

ลาก Button component ของ backdrop (รูปทึบเต็มจอที่อยู่หลัง panel) เข้าช่อง Backdrop Button ใน Inspector ของ UIPopup component แล้วติ๊ก/ปลดติ๊ก Close On Backdrop Click (default ติ๊กอยู่) — ตั้งค่าล้วนๆ ผ่าน Inspector ไม่ต้องเขียนโค้ด ปุ่มเดียวก็คลิกปิดได้ทันที ปลดติ๊กสำหรับ popup ที่ต้องการให้ผู้ใช้เลือกปุ่มเท่านั้น (เช่น ConfirmPopup ในตัวอย่างปลดติ๊กไว้)

Blocker — กันหลุด block ก่อนเวลา

Show<T>/Hide<T> ของ UIBlocker นับ reference count ให้อัตโนมัติ — ถ้ามี 2 ระบบเรียก Show พร้อมกัน (เช่น network request + asset load) แล้วอันหนึ่งเสร็จก่อนแล้วเรียก Hide จะไม่หลุด block ปิดจริงก็ต่อเมื่อจำนวนครั้งที่เรียก Hide ครบเท่ากับจำนวนครั้งที่เรียก Show แล้วเท่านั้น — เรียก API เดียวกับ Screen/Popup ได้เลย ไม่ต้องจำ API แยก:

UIManager.Instance.Show<LoadingBlocker>();  // เรียกได้จากหลายที่พร้อมกัน นับให้เอง
UIManager.Instance.Hide<LoadingBlocker>();

แนวทางการตั้งชื่อ Class

Class ของ UI ทุกตัวที่ผูกกับ catalog (UIView/UIScreen/UIPopup/UIWidget/UIBackground/UIBlocker) ตั้งชื่อด้วย {ความหมาย} + {Suffix ตาม Layer} เสมอ:

LayerBase classSuffixตัวอย่าง
BackgroundUIBackgroundBackgroundAppBackground
ScreenUIScreenScreenMainMenuScreen, SettingsScreen
PopupUIPopupPopupConfirmPopup, RewardPopup
OverlayUIWidgetOverlayHealthOverlay, MinimapOverlay
ToastUIToastToastAchievementToast, SimpleToast
BlockerUIBlockerBlockerLoadingBlocker
  • ไม่ต้องมี prefix UI นำหน้า — namespace/base class บอกอยู่แล้วว่าเป็น UI
  • ชื่อไฟล์ .cs และชื่อ prefab ต้องตรงกับชื่อ class เป๊ะ
  • variant หลายตัวของ layer เดียวกัน เติมคำขยายไว้ หน้า suffix เสมอ — DailyRewardPopup ไม่ใช่ RewardPopupDaily
  • 1 class = 1 suffix เท่านั้น

prefab ที่สร้างผ่าน Canvas Core > Create ไม่ต้องตามกติกานี้ — ไม่ได้ผูกกับ catalog

คำถามที่พบบ่อย

Show/Spawn แล้ว throw Resources.Load<UIView>(...) returned null

prefab ไม่ได้อยู่ใต้โฟลเดอร์ที่ชื่อ Resources เป๊ะ หรือ path ใน catalog entry ไม่ตรงกับตำแหน่งจริง — เปิด entry นั้นใน catalog, ลาก prefab เข้าช่อง "Drag prefab" ใหม่แล้วกด "Sync" เพื่อ resync path/type string

Rename class หรือย้ายไฟล์ .cs แล้ว catalog หา Type ไม่เจอ

UICatalogEntry เก็บ Type เป็น assembly-qualified string ไม่ใช่ object reference ปกติที่ Unity อัปเดตให้อัตโนมัติ — ต้องกด "Sync" ที่ entry นั้นใหม่ทุกครั้งหลัง rename/ย้าย assembly

Show<T>() สร้าง instance ใหม่ทุกครั้งที่เรียก ไม่ reuse จาก pool

เช็คว่า Type นั้นไม่ได้มี entry ซ้ำสองอันใน catalog (ดู HelpBox เตือนสีเหลืองในหัว Inspector) — ถ้ามี entry ซ้ำ แต่ละครั้งอาจ resolve ไปคนละ pool

อยากเปิดหลาย instance ของ Popup/Screen เดียวกันพร้อมกัน ทำไงดี

Show/Hide<T> รองรับ instance เดียวต่อ Type เท่านั้นโดยตั้งใจ — ถ้าต้องการหลาย instance พร้อมกัน (floating text, damage popup ซ้ำๆ) ให้เปลี่ยนไปสืบทอด UIWidget แล้วใช้ Spawn/Despawn แทน

RecycledScrollView โชว์ cell ว่างๆ ตอนเลื่อนเร็วๆ

เพิ่มค่า Overscan Cells ใน Inspector ของ RecycledScrollView — ค่านี้คือจำนวน cell พิเศษที่ pool ไว้เกินขอบเขต viewport กันโชว์ว่างระหว่างเลื่อนเร็ว

อยากลบตัวอย่าง (Examples/) ทิ้ง จะกระทบ framework ไหม

ไม่กระทบเลย — Examples/ อยู่คนละ assembly (Aexxa.CanvasCore.Examples) จาก framework core (Aexxa.CanvasCore.Runtime/.Editor) โดยตั้งใจ ลบทั้งโฟลเดอร์ได้เลย แล้วสร้าง UICatalogSO/UI ของโปรเจ็คตัวเองแทนตามเริ่มต้นใช้งาน

ต้องการ async load prefab จริงๆ (ไม่ block main thread) ทำได้ไหม

ตอนนี้ยังไม่รองรับ — Resources.Load เป็น synchronous call เสมอ (เกิด hitch สั้นๆ แค่ครั้งแรกต่อ Type ไม่ใช่ทุกครั้งที่ spawn) ถ้าต้องการ async/remote content จริงๆ ต้องอัปเกรดเป็น Addressables เอง — ยังไม่มีใน scope ของแพ็คเกจนี้
