CanvasCore — คู่มือใช้งาน

สอนวิธีใช้แต่ละระบบในโปรเจ็คของคุณ ตั้งแต่ setup ครั้งแรก ตัวอย่างที่ก็อปไปใช้ได้เลย best practice และ API ครบทุกตัวในหน้า API Reference  ·  ถ้าอยากรู้ เหตุผลเบื้องหลัง การออกแบบ หรือ TODO ของแต่ละระบบ ดู CanvasCore-Docs.html ที่ root ของโปรเจ็คแทน

เริ่มต้นใช้งาน

  1. รัน Tools > CanvasCore > Import Essential Resources หนึ่งครั้ง (แล้ว Import Examples ถ้าอยากได้ตัวอย่าง)

    ข้อนี้ข้ามไม่ได้ — แพ็คเกจไม่มี asset ที่ Unity มองเห็นเลยแม้แต่ไฟล์เดียว ก่อนกดคำสั่งนี้จึงยังไม่มี CanvasCoreSettings ไม่มี prefab (CanvasCore จะขึ้น error บอกใน Console ไม่ปล่อยให้ทำงานครึ่ง ๆ กลาง ๆ)

    คำสั่งแยกเป็น 2 ตัว เหมือน TMP ที่มี "Essential Resources" กับ "Examples & Extras" ด้วยเหตุผลเดียวกัน:

    • Import Essential Resources — Prefabs/UIRoot.prefab, Prefabs/UIBootstrap.prefab, Resources/CanvasCoreSettings.asset · เท่านี้ CanvasCore ทำงานได้แล้ว (ช่อง Catalog ของ UIBootstrap มาแบบว่าง ตั้งใจ — catalog เป็นของคุณ ถ้า ship มาผูกกับ catalog ตัวอย่างไว้ ของจำเป็นจะกลายเป็นต้องพึ่งตัวอย่าง)
    • Import Examples — prefab ของ Design System, ตารางภาษา en/th, ตัวอย่าง 5 หน้าจอ พร้อมสคริปต์, Examples/Scenes/ExampleScene.unity และไฟล์ตัวอย่างภาษาญี่ปุ่นที่ Assets/StreamingAssets/Localization/ja.csv · ลบทิ้งทีหลังได้ทั้งโฟลเดอร์ (scene ตัวอย่างวาง UIBootstrap ไว้ในนั้น ถ้ายังไม่เคย import essentials มันจะถามให้ลากมาด้วยเลย)

    ทั้งสองคำสั่งไม่ยุ่งกับเมนู GameObject > Canvas Core > Create เพราะเมนูนั้นคือสคริปต์ที่ถูก generate ขึ้นมา และการเขียนสคริปต์ = domain reload ซึ่งไม่ควรโผล่มากลางการ import · อยากได้เมื่อไหร่กด Tools > CanvasCore > Scan Create Menu Prefabs เอง (หรือปุ่ม "Scan & Generate Menu" บน CanvasCoreSettings)

    ทำไมแพ็คเกจถึงว่างเปล่า — ต้นฉบับอยู่ใน PackageResources~/ กับ Samples~/ ซึ่งลงท้ายด้วย ~ และ Unity จะไม่มองโฟลเดอร์ที่ลงท้ายแบบนี้เลย ไม่ import ไม่ compile ไม่มี GUID ไม่เข้า Resources.Load ไม่เข้า build · นี่ไม่ใช่เรื่องความเป็นระเบียบ แต่แก้บั๊กจริง: ตอนที่มันยังเป็น asset ปกติ โปรเจ็คที่ import แล้วจะมี asset สองตัวที่ path Localization/en — ของคุณกับของแพ็คเกจ — และ Resources.Load รับ path ไม่ได้รับ asset จึงไม่การันตีว่าจะคืนตัวไหน dropdown ใน Inspector (ที่กรองเฉพาะ Assets/) กับเกมที่รันอยู่จึงตอบไม่ตรงกันได้ แถวที่คุณแก้ไม่ใช่แถวที่โผล่ · ใน build ยิ่งแก้ไม่ได้เพราะไม่มี AssetDatabase ให้เลือก พอต้นฉบับมองไม่เห็น ความซ้ำก็เกิดไม่ได้ตั้งแต่แรก

    ผลที่ตามมาสองข้อ: สคริปต์ตัวอย่างเป็นของคุณแล้ว — เมื่อก่อนต้องทิ้งไว้ในแพ็คเกจเพราะชื่อ assembly ซ้ำกันทั้งโปรเจ็คไม่ได้ ตอนนี้สำเนาในแพ็คเกจไม่ถูก compile Examples/Scripts/ จึงตามมาด้วย แก้ได้จริงไม่ใช่แค่อ่าน · และ reference ติดมาครบโดยไม่ต้องเขียนใหม่ เพราะ .meta ถูกก๊อปมาทั้งดุ้น (อัปจาก 0.3.0 หรือเก่ากว่า: ตัว import เดิมสร้าง GUID ใหม่ทุกครั้ง การ import รอบนี้จึงย้าย GUID เป็นครั้งสุดท้าย — ของคุณที่อ้างถึง prefab ที่ import ไว้ ต้องลากใส่ใหม่หนึ่งรอบ)

  2. ลาก UIRoot.prefab ลง Scene

    อยู่ที่ Prefabs/UIRoot.prefab — เป็น root Canvas พร้อม 6 Layer (Background/Screen/Popup/Overlay/Toast/Blocker) สำเร็จรูป ไม่ต้องประกอบ Canvas เอง

  3. เพิ่ม UIBootstrap ลงซีน

    ลาก Prefabs/UIBootstrap.prefab ลงไปตรง ๆ ได้เลย (หรือใส่ component UIBootstrap เองบน GameObject ไหนก็ได้) — ถ้าใส่เอง ลาก UIRoot.prefab เข้าช่อง Root Prefab และลาก catalog asset ของคุณ (ดูข้อ 3) เข้าช่อง Catalog — UIBootstrap.Awake() จะ instantiate root + สร้าง UIManager ให้อัตโนมัติตอนเข้า Play

  4. สร้าง UICatalogSO asset ของโปรเจ็คตัวเอง

    คลิกขวาใน Project window → Create > Canvas Core > UI Catalog (ถ้าหาไม่เจอ พิมพ์ "UICatalog" ในช่องค้นหา Create menu) — เก็บไว้ที่ไหนในโปรเจ็คก็ได้ ไม่จำเป็นต้องอยู่ใต้ Plugins/aexxa/

  5. เขียน UI class แรกของคุณ

    สืบทอด UIScreen/UIPopup/UIWidget ตามด้านแนวคิดหลัก แล้ว build prefab คู่กัน วางไว้ใต้โฟลเดอร์ที่ชื่อ Resources เป๊ะ (ดูเหตุผลในCatalog Inspector)

  6. เปิด catalog asset → กด "Scan Resources/UI"

    ระบบจะหา prefab ที่มี UIView component ทุกตัวใต้โฟลเดอร์ Resources แล้วเพิ่ม entry ให้เอง พร้อมเดา layer และตั้งค่า pool ที่เหมาะสมให้ทันที

  7. เรียกจากโค้ดเกม

    UIManager.Instance.Show<SettingsScreen>();

    เท่านี้จบ — อยากเห็นของจริงที่รันได้ เปิด Examples/Scenes/ExampleScene.unity (มีหลัง import ตามข้อ 1) กด Play (มี Examples/README.md บอกว่าอยากเรียนเรื่องไหน ให้เปิดไฟล์ไหน) ดูตัวอย่างทั้งหมดใน Examples/ (ลบทิ้งได้เมื่อพร้อมเริ่มสร้าง UI ของตัวเอง)

isStacked = true แปลว่าเปิดตัวใหม่แล้วตัวก่อนหน้าใน layer เดียวกันจะถูกซ่อนอัตโนมัติ (ไม่ได้ despawn) — ปิดตัวบนสุดแล้วตัวที่ซ่อนไว้จะโชว์กลับมาเอง เหมาะกับ Screen/Popup ที่นำทางเป็นลำดับ

เลือก base class ให้ถูก

UIScreen

ใช้กับ Show<T>() / Hide<T>() — instance เดียวต่อ Type เท่านั้น layer เป็น isStacked = true เข้าคิว back-stack ให้อัตโนมัติ ติ๊ก Is Root Screen ใน Inspector สำหรับจอที่เป็นฐานของ navigation (HUD/MainMenu) เพื่อกัน HandleBack() ปิดจอนี้ทิ้ง

UIPopup

ใช้ Show<T>() / Hide<T>() เหมือนเดิม แต่มีคิวในตัว: มีได้แค่ 1 popup บนจอพร้อมกันเสมอ ไม่ว่าจะเป็น type เดียวกันหรือคนละ type ถ้าเรียก Show ตอนที่มี popup อื่นเปิดอยู่ คำขอนั้นจะเข้าคิวรอแทนที่จะไปทับ/แย่งของเดิม แล้วโชว์เองอัตโนมัติตามลำดับที่เปิดปิดจริง — ลาก Button ของ backdrop เข้าช่อง Backdrop Button แล้วได้คลิกนอกกรอบปิดฟรี ปลดติ๊ก Close On Backdrop Click ใน Inspector สำหรับ popup ที่ต้องการให้เลือกปุ่มเท่านั้น (เช่น confirm dialog)

UIWidget / UIToast

ใช้กับ Spawn<T>() / Despawn() — สร้างได้หลาย instance พร้อมกัน (floating damage text, toast ซ้อนกัน) UIToast เป็น UIWidget ที่ auto-dismiss ตัวเองตาม duration ให้แล้ว

UIBackground

ใช้กับ Show<T>() / Hide<T>() เหมือน UIScreen/UIPopup — instance เดียวต่อ Type แต่ layer เป็น isStacked = false จึงไม่เข้าคิว back-stack และไม่ตอบสนอง HandleBack() เหมาะกับของที่โชว์/ซ่อนแบบอิสระตลอดเกม (backdrop)

UIBlocker

เหมือน UIBackground (isStacked = false) แต่ Show<T>()/Hide<T>() นับ reference count ให้อัตโนมัติ — เรียก API เดียวกัน ไม่ต้องจำ method แยก — กัน 2 ระบบเรียก block พร้อมกันแล้วอันหนึ่งปล่อยก่อนจนอีกอันหลุด block ไปด้วย

ทั้ง 5 base class สืบทอดจาก UIView โดยตรง (ยกเว้น UIToast : UIWidget) — Catalog Inspector ใช้ type นี้เดา layer/pool defaults ให้อัตโนมัติตอนกด "Scan and add missing entries" ดังนั้นเลือก base class ให้ตรงกับ layer ที่ตั้งใจใช้จริงเสมอ

ทำไม prefab ต้องอยู่ใน Resources/

UICatalogEntry เก็บ prefab เป็น string resourcePath ไม่ใช่ direct reference — เพื่อไม่ให้ Unity โหลดทุก prefab ใน catalog เข้า RAM ตั้งแต่ scene เปิด (ผลข้างเคียงของกติกา eager-load ของ direct reference) prefab แต่ละตัวจะถูกโหลดจริงผ่าน Resources.Load ก็ต่อเมื่อ pool ของ Type นั้นถูกสร้างครั้งแรกเท่านั้น (ตอน prewarm หรือตอน Show/Spawn ครั้งแรก) — นี่คือเหตุผลที่ต้องวางไฟล์ไว้ใต้โฟลเดอร์ที่ชื่อ Resources เป๊ะ

Pooling

ทุก UIView ถูก pool ผ่าน UnityEngine.Pool.ObjectPool<T> อัตโนมัติ — implement IPoolable lifecycle 3 จุดถ้าต้องการ:

public override void OnCreated()   { /* ครั้งแรกที่ instantiate เท่านั้น — wire onClick ที่นี่ */ }
public override void OnSpawn(object context) { /* ทุกครั้งที่ Show/Spawn — รับค่าที่ส่งเข้ามา */ }
public override void OnDespawn()   { /* ทุกครั้งที่ Hide/Despawn — เคลียร์ state/callback ค้าง */ }

สร้าง UI ใหม่ — ตัวอย่างเต็ม

using Aexxa.CanvasCore;
using TMPro;
using UnityEngine;
using UnityEngine.UI;

public sealed class RewardPopup : UIPopup
{
    [SerializeField] private TMP_Text titleText;
    [SerializeField] private Button claimButton;

    public readonly struct Context
    {
        public readonly string Title;
        public Context(string title) => Title = title;
    }

    public override void OnCreated()
    {
        claimButton.onClick.AddListener(HandleClaim);
    }

    public override void OnSpawn(object context)
    {
        titleText.text = ((Context)context).Title;
    }

    private void HandleClaim()
    {
        UIManager.Instance.Hide<RewardPopup>();
    }
}

  1. Build prefab

    root ต้องมี CanvasGroup (component ที่ UIView ต้องการ) — สร้าง GameObject ว่างๆ แล้ว Add Component RewardPopup ได้เลย ระบบจะเติม CanvasGroup ให้ผ่าน Reset()

  2. วางไว้ใต้ Resources/UI/Popup/Reward/RewardPopup.prefab

    ตั้งชื่อโฟลเดอร์ตาม layer ก่อนแล้วค่อยตามชื่อ element เอง (ดูตัวอย่างจริงใน Examples/Resources/UI/)

  3. เปิด catalog → "Scan Resources/UI"

    หรือกด "+ Add Entry" แล้วลาก prefab เข้าช่อง "Drag prefab" กด "Sync" เอง

  4. เรียกใช้

    UIManager.Instance.Show<RewardPopup>(new RewardPopup.Context("ยินดีด้วย!"));

Localization — ทำเกมหลายภาษา

ระบบแปลข้อความในตัว ไม่ต้องติดตั้งแพ็คเกจเพิ่ม หลักการเดียวที่ต้องจำ: key เป็นของโปรเจ็ค ส่วนคำแปลเป็นของแต่ละภาษา — ทุกภาษามี key ครบเท่ากันเสมอ ภาษาที่ยังไม่ได้แปลบอกด้วยค่าว่าง ไม่ใช่ด้วยการไม่มีแถวนั้น

เริ่มใช้ใน 3 ขั้น

  1. สร้างภาษาแรก

    Tools > CanvasCore > Localization > Create Locale Table... กรอก locale code (en, th — ใช้รหัส ISO 639-1 สองตัวอักษร), ชื่อที่จะโชว์ในเมนู (เขียนด้วยภาษานั้นเอง เช่น "ไทย" ไม่ใช่ "Thai") และ SystemLanguage ที่จะให้ auto-detect เดาเข้าภาษานี้ กด Create แล้วมันสร้าง asset ใต้ Examples/Resources/Localization/ + ลงทะเบียนใน CanvasCoreSettings ให้เอง

    ทำซ้ำสำหรับภาษาที่สอง — ตอนสร้างจะติ๊ก "Seed With Existing Keys" ไว้ ทำให้ได้ key ทั้งหมดจากภาษาแรกมาเป็นค่าว่างรอแปลเลย

  2. ใส่ข้อความ

    เปิด asset ของภาษานั้นแล้วกด + Add Key พิมพ์ key แล้ว กด Enter — key จะถูกเพิ่มเข้าทุกภาษาพร้อมกันอัตโนมัติ เหลือแค่ไปพิมพ์คำแปลของแต่ละภาษา

    รูปแบบ key ที่แนะนำ: <เจ้าของ>.<ส่วนประกอบ>[.<บทบาท>] ตัวเล็กคั่นจุด เช่น mainmenu.button.settings, common.back, inventory.cell.item — จุดทำให้ dropdown เลือก key จัดเป็นเมนูซ้อนให้อัตโนมัติ และตารางเรียงตาม key ทำให้ string ของหน้าเดียวกันกองอยู่ด้วยกัน

  3. เอาไปแปะบน UI

    เลือก TMP_Text ที่ต้องการ → Add Component → Canvas Core > Localized Text → เลือก key จาก dropdown (มี preview คำแปลให้เห็นใต้ช่อง) — จบ ไม่ต้องเขียนโค้ดในหน้าจอนั้นเลย label จะเปลี่ยนภาษาตามเองตลอดไป

อย่าลืมเช็ค font: Tools > CanvasCore > Localization > Font Coverage... — ถ้าภาษาที่เพิ่มใช้ตัวอักษรที่ font ในโปรเจ็คไม่มี ทุกอย่างจะถูกต้องหมดยกเว้นบนจอที่เป็น □□□□ เครื่องมือนี้เอาตัวอักษรที่คำแปลของคุณใช้จริงไปถามทีละ font ว่าวาดตัวไหนไม่ได้ พร้อมปุ่มสร้าง TMP font asset จาก .ttf และตั้งเป็น fallback ของทั้งโปรเจ็คให้ในคลิกเดียว (fallback ระดับ TMP Settings = TMP_Text ทุกตัวยืม glyph ไปใช้ได้โดยไม่ต้องแก้ prefab สักอัน)

ให้ font เปลี่ยนตามภาษา

ภาษาไทยปนอังกฤษในประโยคเดียวใช้ fallback font ดีที่สุด (ตั้งครั้งเดียวที่ TMP Settings แล้วทุก label ยืม glyph ได้เลย ไม่ต้องแก้ prefab) แต่ถ้าอยากให้ทั้งภาษาหน้าตาเปลี่ยนไปเลย — เช่นญี่ปุ่นควรใช้ font ญี่ปุ่นทั้งประโยค ไม่ใช่ยืมเฉพาะ kana — ให้สลับ font asset ตรง ๆ แทน ทำ 2 ขั้น:

  1. เอา TMP font asset ไปไว้ใต้โฟลเดอร์ชื่อ Resources (ที่ไหนก็ได้) แล้วกรอก path ลงช่อง Font Resource Path ของภาษานั้นใน CanvasCoreSettings เช่น Localization/Fonts/NotoSansJP SDF — เขียนโดยไม่ใส่นามสกุลไฟล์ ถ้ากรอกผิด Inspector เตือนให้ทันที
  2. แปะ LocalizedFont ไว้ที่ root ของ screen ครั้งเดียว — มันครอบ TMP_Text ทุกตัวข้างใต้ รวมตัวที่ปิดอยู่ ไม่ต้องแปะทีละ label

ภาษาที่ไม่ได้กรอก path ไว้ = "ไม่มีความเห็น" label จะกลับไปใช้ font ที่ prefab ตั้งไว้เดิม ดังนั้นแปะ LocalizedFont ไว้ล่วงหน้าได้เลยโดยไม่มีผลอะไรจนกว่าจะมีภาษาไหนระบุ font จริง ๆ

ถ้าภาษานั้นต้องการบรรทัดห่างขึ้น ตั้ง Line Spacing Adjustment (หรือ locale.linespacing,10 ในไฟล์ CSV) — ค่านี้ถูกบวกเข้ากับ Line Spacing ที่ prefab ตั้งไว้ ไม่ใช่คูณ เพราะ lineSpacing ของ TMP เริ่มที่ 0 ตัวคูณจึงไม่มีผลอะไรเลย · ภาษาไทยที่ซ้อนสระกับวรรณยุกต์บน-ล่างมักต้องการค่านี้

ถ้าภาษานั้นต้องการตัวหนังสือใหญ่กว่าเดิม ตั้ง Font Size Scale ของ locale นั้น (หรือแถว locale.fontscale,1.2 ในไฟล์ CSV) — LocalizedFont จะคูณกับขนาดที่ prefab ตั้งไว้ให้ทุก label ใต้มัน และกลับเป็นขนาดเดิมเมื่อสลับไปภาษาที่ไม่ได้ขอ · มีประโยชน์กับ CJK ที่ขนาดซึ่งภาษาอังกฤษอ่านสบาย มักจะเล็กเกินไป

ภาษาที่ผู้เล่นเพิ่มเองก็เลือก font ได้ — ใส่แถว locale.font,Localization/Fonts/NotoSansJP SDF ลงในไฟล์ CSV (คู่กับ locale.displayname) โดย font ตัวนั้นต้องมีอยู่ในบิลด์แล้ว — CSV ชี้ font ได้ แต่แถม font มาเองไม่ได้ · ถ้าไฟล์ระบุ font มันชนะค่าใน settings

sprite / เสียง ที่ต่างกันตามภาษา

ใช้ LocalizedAsset<T> ประกาศเป็น field ได้เลย ทุกอย่างเป็น Resources path เหมือนกันหมด:

[SerializeField] private LocalizedAsset<Sprite> banner;      // Default: "UI/Banner"  |  th → "UI/Banner_th"
[SerializeField] private LocalizedAsset<AudioClip> greeting;

image.sprite = banner.Load() ?? image.sprite;       // null = ภาษานี้ไม่มีของ ใช้ของเดิม
if (greeting.TryLoad(out var clip)) source.PlayOneShot(clip);

ถ้าเป็น Image ธรรมดาที่แค่อยากสลับรูป ใช้ component LocalizedImage แทนได้เลย ไม่ต้องเขียนโค้ด — ทำงานแบบเดียวกับ LocalizedText ทุกอย่าง ส่วนเสียง/วิดีโอไม่มี component ให้ เพราะ "ควรสลับตอนไหน" ไม่มีคำตอบที่ถูกเสมอ

เช็คว่า key ครบไหม ก่อนจะไปเจอ #key# บนจอ

Tools > CanvasCore > Localization > Key Usage... แล้วกด Scan — มันอ่านทั้ง Localization.Get("...") ในโค้ด และ key ที่ตั้งไว้ใน Inspector (prefab / scene / asset) แล้วบอก 2 อย่าง:

  • ใช้แต่ไม่มีในตาราง — พวกนี้จะขึ้นเป็น #key# บนจอจริง กดปุ่มเดียวเพิ่มเข้าทุกภาษาได้เลย
  • มีในตารางแต่หาที่ใช้ไม่เจอ — แค่ติดธงไว้ให้ดู ไม่ลบให้ เพราะ key ที่ประกอบตอน runtime อย่าง Get("item." + id) ไม่มีทางสแกนเจอ และมันจะโผล่ในลิสต์นี้เหมือนกัน เช็คด้วยตาก่อนลบเสมอ

สแกน scene ช้าที่สุด (ต้องโหลดทีละ scene) กดปิดหัวข้อ Scenes บนแถบเครื่องมือได้ถ้าอยากได้ผลเร็ว ๆ · การสแกน scene ไม่กระทบ scene ที่เปิดค้างไว้อยู่

ข้อความเป็นกล่องสี่เหลี่ยม □□□□

RecycledScrollView — List ยาวๆ

list ปกติที่ instantiate 1 GameObject ต่อ 1 item จะพังเมื่อ item เยอะ (1000+) — RecycledScrollView instantiate cell แค่เท่าที่ viewport แสดงได้ (+ overscan buffer) แล้ว rebind ซ้ำตาม index ที่เลื่อนเข้ามา ไม่ว่าจะมีกี่ item

1. เขียน cell ที่ implement IRecycledScrollCell

using Aexxa.CanvasCore;
using TMPro;
using UnityEngine;

public sealed class ItemCell : MonoBehaviour, IRecycledScrollCell
{
    [SerializeField] private TMP_Text label;

    public void Bind(int index)
    {
        label.text = MyDataSource.Items[index].Name;
    }
}

2. Build cell prefab + scroll view

เร็วสุดคือลาก Examples/Prefabs/DesignSystem/ScrollView.prefab ลง Scene (มี ScrollRect/RecycledScrollView wire ไว้ครบแล้ว รอแค่ assign Cell Prefab) แล้วสร้าง cell prefab ของตัวเองแยกลาก assign เข้าช่อง Cell Prefab ใน Inspector — ปรับ Cell Size ให้ตรงความสูงจริงของ cell

3. เรียกใช้จากโค้ด

[SerializeField] private RecycledScrollView scrollView;

private void Start()
{
    scrollView.SetItemCount(MyDataSource.Items.Count);
}

// list เปลี่ยน (filter/sort/reload) — เรียกซ้ำได้เสมอ
private void OnFilterChanged() => scrollView.SetItemCount(MyDataSource.FilteredCount);

// ข้อมูลเปลี่ยนแต่จำนวน/ตำแหน่ง scroll เดิม — rebind เฉพาะที่เห็นอยู่ ไม่ reset scroll
private void OnDataMutated() => scrollView.Refresh();
ข้อควรระวัง: ถ้าเรียก SetItemCount() จาก OnCreated() ของ UIView (เช่นเดียวกับตัวอย่าง InventoryScreen) ระบบจะ force Canvas.ForceUpdateCanvases() ให้อัตโนมัติภายในเพื่อวัดขนาด viewport ให้แม่นตั้งแต่เฟรมแรก — ไม่ต้องกังวลเรื่อง pool เล็กเกินไปเพราะ layout ยังไม่ settle

โหมดอื่น: แนวนอน / ความสูงไม่เท่ากัน / กริด

ตั้งที่ Inspector ของ RecycledScrollView ทั้งหมด ไม่ต้องเปลี่ยน cell หรือโค้ดที่เรียก

อยากได้ตั้งอะไรข้อควรรู้
ลิสต์แนวนอนAxis = Horizontalอย่าลืมสลับ Horizontal/Vertical ที่ ScrollRect ให้ตรงกันด้วย — ตัวนั้นคุมการลาก อันนี้คุม content
กริด (ช่องเก็บของ)Layout Mode = Grid + Cross Axis Countcell จะถูกกำหนดขนาดตามจำนวนคอลัมน์ ไม่ยืดเต็มความกว้างเหมือนลิสต์ธรรมดา
แต่ละแถวสูงไม่เท่ากันLayout Mode = Variable Size + SetSizeProvider()ต้องเรียก SetSizeProvider ก่อน SetItemCount เสมอ (ดูกล่องด้านล่าง)
 
// ความสูงไม่เท่ากัน — provider ต้องตอบได้ทุก index ตอนนั้นเลย
scrollView.SetSizeProvider(index => messages[index].IsImage ? 180f : 48f);
scrollView.SetItemCount(messages.Count);

scrollView.ScrollTo(messages.Count - 1);   // เลื่อนน้อยที่สุดเท่าที่จะเห็นแถวล่าสุด
ทำไม Variable Size ต้องรู้ความสูงล่วงหน้า — มันบวกความสูงสะสมไว้ทั้งลิสต์ตอน SetItemCount เพื่อให้หา "index ไหนอยู่ที่ตำแหน่ง scroll นี้" ด้วย binary search ได้ (ลิสต์หมื่นแถวก็ ~13 ครั้งเปรียบเทียบ แทนที่จะไล่ทีละแถวทุกเฟรม) ถ้าความสูงขึ้นกับข้อความที่ต้อง render จริง ให้ประมาณเอาก่อน — ทางเลือกคือวัดตอน bind ซึ่งจะทำให้ขนาด content เปลี่ยนระหว่างผู้เล่นกำลังเลื่อน = scrollbar ขยับใต้นิ้ว

ข้อจำกัด

  • รองรับแค่ vertical scroll, fixed cell height เท่ากันทุกอัน (v1)
  • ห้ามใส่ LayoutGroup/ContentSizeFitter บน Content — RecycledScrollView คุม anchor/size ของมันเองเต็มที่ ใส่ซ้อนจะแย่งกันคุม

  2. จบแล้ว — เปิดจอไหนก็ตาม ไฟจะไปอยู่ที่ปุ่มแรกที่กดได้ให้เอง ปิด popup แล้วไฟกลับไปที่ปุ่มเดิมที่กดเปิดมันให้เอง
โดย default จะยังไม่เห็นไฟอะไรเลยจนกว่าจะกดทิศทาง — ตั้งใจครับ ผู้เล่นเมาส์ไม่ควรเห็นไฟค้างบนปุ่มที่ไม่ได้แตะ พอกดลูกศร/d-pad/สติ๊กครั้งแรกเมื่อไหร่ ระบบถึงเข้าคุม · พอผู้เล่นกลับไปขยับเมาส์/คลิก ไฟจะดับเองด้วย — สลับไปมาได้ตลอด · อยากให้ขึ้นไฟตั้งแต่แรกและไม่สนใจเมาส์เลย (เกมที่เน้นจอย) เปลี่ยน Focus Mode ใน CanvasCoreSettings เป็น Always

สั่งให้ไฟไปอยู่ตรงที่ต้องการ

ถ้าปุ่มแรกที่ระบบเดาให้ไม่ใช่ปุ่มที่ควรโฟกัส (เช่นเจอปุ่ม Cancel ก่อน) ตั้งช่อง First Selected บน UIView ของจอนั้น ลากปุ่มที่ต้องการใส่ไป — แค่นั้น

// ย้ายไฟเองตอน runtime (เช่นหลังโหลดข้อมูลเสร็จค่อยโฟกัสปุ่มแรกของลิสต์)
UIManager.Instance.Focus.Select(myButton.gameObject);

// เปลี่ยนนโยบายกลางเกม เช่นมีสวิตช์ "โหมดจอย" ในหน้า Settings
UIManager.Instance.Focus.Mode = UIFocusMode.Always;

ทำให้เห็นว่าตอนนี้อยู่ปุ่มไหน

ถ้าเลื่อนแล้วไม่เห็นอะไรเปลี่ยน ไม่ใช่ว่าระบบไม่ทำงาน — ค่า default ของ Unity ตั้งสี "ถูกเลือก" ไว้เข้มลงแค่ 4% ซึ่งบนปุ่มสีจัดหรือปุ่มสีเข้มมองไม่ออกเลย

ปุ่มจาก Examples/Prefabs/DesignSystem/Button.prefab ใส่ UISelectionIndicator มาให้แล้ว (กรอบสีทองรอบปุ่ม) ถ้าทำปุ่มเอง ใส่ 2 ขั้น:

  1. สร้างลูกใต้ปุ่มเป็นภาพกรอบ (Image แบบ Sliced ติ๊ก Fill Center ออก จะได้เป็นวงแหวน ไม่ทับหน้าปุ่ม) แล้วปิด GameObject ไว้
  2. ใส่ UISelectionIndicator ที่ตัวปุ่ม แล้วลากกรอบนั้นเข้าช่อง Indicator

ทำไมไม่ใช้แค่เปลี่ยนสี: ไฮไลต์ที่ต้องอยู่รอดทุกสีปุ่ม ทุกธีม และโหมดมืด เป็นเฉดสีของสิ่งที่มันไฮไลต์อยู่ไม่ได้ · กรอบนี้ไม่ขึ้นตอนเมาส์ชี้ เพราะ hover มีวิชวลของตัวเองแล้ว

เปลี่ยนปุ่มที่ใช้ / ให้ผู้เล่น rebind ได้

ปุ่ม default (ลูกศร, d-pad, สติ๊กซ้าย, Esc, B/Circle) เป็นแค่ค่าเริ่มต้นให้ใช้ได้ทันที ถ้าโปรเจ็คมี Input Actions ของตัวเอง เขียน class เดียวแล้วเสียบ:

public sealed class MyInput : IUINavigationInput
{
    public bool NavigatedThisFrame()       => _actions.UI.Navigate.WasPressedThisFrame();
    public bool CancelPressedThisFrame()   => _actions.UI.Cancel.WasPressedThisFrame();
    public bool PointerActivityThisFrame() => _actions.UI.Point.WasPerformedThisFrame();
}

UINavigationInput.Source = new MyInput();   // ครั้งเดียวตอนเริ่มเกม

ปุ่มที่ผู้เล่น rebind เองก็ทำงานทันที เพราะ CanvasCore ถามผ่านท่อนี้ ไม่ได้ไปอ่านปุ่มเอง · Submit (Enter/A) ไม่ต้องทำอะไร — EventSystem ของ Unity จัดการเองอยู่แล้ว

ลิสต์ยาว ๆ กับจอย — ต้องใช้ RecycledScrollNavigator

อย่าใส่ Button ในแต่ละ cell แล้วหวังว่าจอยจะเลื่อนได้ มันจะพัง และไม่ใช่ความผิดคุณ: ลิสต์แบบ recycle ไม่มี GameObject ต่อ item — พอ cell ถูกใช้ซ้ำ ไฟจะไปอยู่ผิดแถว และ item ที่กำลังจะเลื่อนไปหายังไม่มี GameObject ให้ Unity หาเจอด้วยซ้ำ

วิธีที่ถูก: แปะ RecycledScrollNavigator ไว้บน GameObject เดียวกับ RecycledScrollView แล้วให้ cell วาดสถานะ selected เอง

public class ItemCell : MonoBehaviour, IRecycledScrollCell, IRecycledScrollCellSelection
{
    [SerializeField] private Image highlight;

    public void Bind(int index) { /* ... */ }

    public void SetSelected(bool selected) => highlight.enabled = selected;   // ลิสต์เป็นคนบอกว่าแถวไหนถูกเลือก
}
navigator.Submitted += index => UseItem(index);        // กด A / Enter
navigator.SelectionChanged += index => preview.Show(index);

ดูของจริงได้เลย — หน้า Inventory ในตัวอย่าง (2,000 แถว) ต่อไว้ให้แล้ว เปิดขึ้นมาแล้วกดลูกศรลงค้างไว้ · โค้ดอยู่ที่ Examples/Scripts/Screens/Inventory/ ทั้ง cell และ screen

กดลงจนสุดลิสต์แล้วจะ "ตกออก" ไปยัง UI ตัวถัดไปตามปกติ (เปิด Wrap Around ถ้าอยากให้วนกลับขึ้นบนแทน) · cell ไม่ต้องมี Selectable ของตัวเอง และไม่ควรมี

ปุ่ม Back / Cancel

UIBootstrap จับให้อยู่แล้วทั้ง Escape (ปุ่ม back ของ Android มาลงที่นี่) และ B/Circle ของจอย แล้วเรียก HandleBack() ให้ — ปิด popup บนสุดก่อน ถ้าไม่มีก็ถอย screen ปิดสวิตช์ Auto Handle Back Input ถ้าจะจัดการเองด้วย Input Actions ของโปรเจ็ค

ปัญหาที่เจอบ่อย

อาการสาเหตุที่พบบ่อยที่สุด
เลื่อนได้ ปุ่มถูกเลือกจริง แต่ไม่เห็นไฟอะไรเลยสี selected ของ Unity เข้มลงแค่ 4% — มองไม่เห็นบนปุ่มสีจัด/สีเข้ม ใส่ UISelectionIndicator (ดูหัวข้อด้านบน)
จอยไม่ทำอะไรเลย ไม่มี errorไม่มี EventSystem ในซีน (เช็ค console จะมี warning) หรือ Focus Mode = Never
กดทิศทางแล้วเงียบไปเฉย ๆ กลางคันปุ่มที่เลือกอยู่ถูกซ่อน/ทำลาย Unity เลยตั้ง selection เป็น null — Focus.Tick() ซ่อมให้ทุกเฟรม ถ้าสร้าง UIManager เองอย่าลืมเรียกมันด้วย
จอยเดินทะลุไปกดปุ่มหลัง popup ได้view นั้นไม่ได้สืบทอด UIPopup — ตัวที่บล็อกข้างล่างคือ Popup กับ Blocker เท่านั้น
ไฟอยู่ผิดแถวในลิสต์ใส่ Selectable ไว้ใน cell — ใช้ RecycledScrollNavigator + IRecycledScrollCellSelection แทน

GameObject > Canvas Core > Create

เมนูสร้าง element จาก prefab แบบคลิกเดียว เหมือน GameObject > UI > Button ของ Unity เอง — ต่างจาก catalog ตรงที่ไม่เกี่ยวกับ UIView/Show-Hide เลย ใช้สำหรับ element ย่อยที่อยาก drag ลง scene ซ้ำๆ ได้ง่าย (ปุ่ม, การ์ด, หรือ GameObject อะไรก็ได้)

  1. เปิด Resources/CanvasCoreSettings.asset

    ตั้งค่า "Prefab Folder" เป็นโฟลเดอร์ที่จะสแกน (default คือ Examples/Prefabs/DesignSystem/ ซึ่งมี Button.prefab/ScrollView.prefab เป็นตัวอย่างอยู่แล้ว) — ลากโฟลเดอร์เข้าไปตรงๆ เหมือนฟิลด์ "Default Style Sheet" ของ TMP Settings

  2. วาง prefab ที่ต้องการเข้าไปในโฟลเดอร์นั้น

    ชื่อ prefab อะไรก็ได้ ไม่มีข้อบังคับ — ชื่อ prefab จะกลายเป็น label ของเมนูตรงๆ

  3. กด "Scan & Generate Menu"

    หรือเมนู Tools > CanvasCore > Scan Create Menu Prefabs — เขียนไฟล์ [MenuItem] จริงให้ ไม่ใช่ popup/dropdown

  4. ใช้งาน

    คลิกขวาใน Hierarchy (หรือเมนู GameObject) → Canvas Core > Create > {ชื่อ prefab} — ถ้า context เป็น RectTransform จะ parent เข้าใต้นั้น ไม่งั้นหา/สร้าง Canvas ให้อัตโนมัติ

การสแกนเป็น action ที่ต้องสั่งเอง ไม่มี background watcher คอย regenerate อัตโนมัติทุกครั้งที่ไฟล์เปลี่ยน — กันไม่ให้ recompile กระตุกโดยไม่ทันตั้งตัวตอนแก้ prefab บ่อยๆ

Back Button / ESC และ Toast

Back Button

UIBootstrap ต่อสาย Escape/Android back button ให้อัตโนมัติ (ตรวจ Input System/Legacy Input Manager ให้เองตาม project settings) — ปิด view บนสุดของ stacked layer ที่ priority สูงสุด (Popup ก่อน Screen เสมอ) ปิด toggle Auto Handle Back Input บน UIBootstrap ถ้าอยากต่อสายเอง แล้วเรียกตรงๆ:

UIManager.Instance.HandleBack();

ถ้า view บนสุดเป็น UIScreen ที่ติ๊ก Is Root Screen ไว้ใน Inspector (เช่น HUD/MainMenu ที่ไม่มีอะไรอยู่ข้างใต้) HandleBack() จะไม่ปิดแล้วคืน false แทน — ให้โค้ดเกมเช็ค return value แล้วต่อ logic exit-confirm ของตัวเองได้ (ดูตัวอย่างจริงใน MainMenuScreen.prefab)

Toast

สืบทอด UIToast แทน UIWidget เฉยๆ — ได้ auto-dismiss ตาม duration ให้ฟรี ไม่ต้องเรียก Hide/Despawn เอง:

UIManager.Instance.Toast<SimpleToast>("บันทึกเรียบร้อย", duration: 2f);

Popup — คิวในตัว ไม่ทับกัน

Show<T>() ของ UIPopup มีคิวในตัว — เรียกได้จากหลายจุดในโค้ดพร้อมกัน (เช่น ระบบ error กับระบบ reward ทั้งคู่เรียก Show เกือบพร้อมกัน) โดยไม่ต้องกลัวว่าอันหลังจะไปทับ context ของอันแรกที่ผู้ใช้ยังไม่ได้ตอบ:

UIManager.Instance.Show<ConfirmPopup>(new ConfirmPopup.Context("ลบไฟล์?", "...", OnConfirmDelete, null));
// เรียกจากอีกจุดนึงเกือบพร้อมกัน — อันนี้เข้าคิว ไม่ไปแย่ง popup ด้านบนที่ยังค้างอยู่
UIManager.Instance.Show<ConfirmPopup>(new ConfirmPopup.Context("ออกจากเกม?", "...", OnConfirmQuit, null));

popup แรกปิด (ไม่ว่าจะกดปุ่ม, คลิก backdrop, หรือกด back) popup ที่สองจะโชว์เองอัตโนมัติตามลำดับที่เรียก — ใช้ API เดิม Show<T>() ทุกอย่าง ไม่มี method ใหม่ให้เรียก

ยกเลิก popup ที่ยังไม่ถึงคิว

popup ที่เข้าคิวรออยู่ (ยังไม่โชว์) ยกเลิกด้วย Hide<T>() ไม่ได้ — ตัวนั้นแก้ได้แค่ popup ที่กำลังโชว์อยู่บนจอเท่านั้น ใช้ 2 เมธอดนี้แทนสำหรับล้างคิว:

UIManager.Instance.CancelQueued<ConfirmPopup>();  // ล้างเฉพาะ type นี้ที่รอคิวอยู่
UIManager.Instance.ClearPopupQueue();               // ล้างทุก popup ที่รอคิว ไม่ว่า type ไหน

ทั้งคู่ไม่แตะ popup ที่กำลังโชว์อยู่บนจอ (ใช้ Hide<T>()/Close() สำหรับตัวนั้น) และปล่อย instance ที่ถูกยกเลิกกลับ pool ผ่าน OnDespawn() ตามปกติ — เรียก ClearPopupQueue() จากโค้ดจัดการ scene transition/reset state ของเกมเองตรงจุดที่ popup ที่ค้างคิวไม่มีความหมายแล้ว (เช่น ก่อนโหลด level ใหม่ กัน popup ของ level เก่าไปโผล่ใน level ใหม่)

ทั้งสองเมธอดนี้เป็นแค่เครื่องมือให้เรียกเอง (opt-in) — ไม่ได้ตรวจจับ reference เสียให้อัตโนมัติ popup ที่รอคิวอาจถูกถือ context ไว้นานแค่ไหนก็ได้ก่อนถึงตาโชว์จริง ถ้า context capture reference ของ object ใน scene (เช่น callback ที่เรียก method ของ enemy ตัวหนึ่ง) แล้ว object นั้นถูก destroy ไปโดยที่ไม่มีใครเรียก ClearPopupQueue()/CancelQueued<T>() popup นั้นจะยังโผล่ตามคิวปกติแล้ว callback จะพังตอนถูกเรียก — framework ตรวจจับกรณีนี้เองไม่ได้ (context เป็น object/Action ทั่วไป ไม่มีทางรู้ว่าข้างในอ้างถึงอะไรบ้าง) ดังนั้น:
  • clear reference ที่ capture ไว้ใน OnDespawn() เสมอ (ดูตัวอย่างใน ConfirmPopup.OnDespawn()) — ช่วยตอนถูกยกเลิกผ่าน 2 เมธอดด้านบน แต่ไม่ช่วยถ้า popup โผล่ขึ้นมาแสดงจริงพร้อม callback เสีย
  • เรียก ClearPopupQueue()/CancelQueued<T>() เชิงรุกตรงจุดที่รู้ว่า state ที่ popup อ้างถึงกำลังจะหายไป (scene unload, player death, object pool recycle ฯลฯ) — อย่ารอให้ popup ไปเจอเอง

จำกัดความยาวคิว

คิวไม่ยาวไม่จำกัด — UIManager constructor รับ maxQueuedPopups (default 20) ถ้าคิวเต็ม Show<T>() ครั้งถัดไปจะถูกตัดทิ้งทันที (ไม่โชว์ ไม่เข้าคิว ปล่อยกลับ pool ผ่าน OnDespawn() เหมือนถูกยกเลิก) พร้อม Debug.LogWarning บอกชื่อ type ที่โดนตัด — กันเคส bug จริง เช่น มีจุดไหนเผลอเรียก Show<Popup>() ในลูปหรือทุกเฟรมโดยไม่ได้ตั้งใจ ไม่ให้คิวบวมไม่จำกัด ค่า return ของ Show<T>() ยังเป็น instance จริงเสมอ (ไม่ใช่ null) ตาม contract เดิม แค่ไม่เคยถูกโชว์เท่านั้น

// ปรับ cap เองได้ตอนสร้าง UIManager (ปกติ UIBootstrap เป็นคนสร้างให้อยู่แล้วด้วยค่า default)
new UIManager(catalog, root, maxQueuedPopups: 50);

Popup — ปิดเมื่อคลิกนอกกรอบ

ลาก Button component ของ backdrop (รูปทึบเต็มจอที่อยู่หลัง panel) เข้าช่อง Backdrop Button ใน Inspector ของ UIPopup component แล้วติ๊ก/ปลดติ๊ก Close On Backdrop Click (default ติ๊กอยู่) — ตั้งค่าล้วนๆ ผ่าน Inspector ไม่ต้องเขียนโค้ด ปุ่มเดียวก็คลิกปิดได้ทันที ปลดติ๊กสำหรับ popup ที่ต้องการให้ผู้ใช้เลือกปุ่มเท่านั้น (เช่น ConfirmPopup ในตัวอย่างปลดติ๊กไว้)

Blocker — กันหลุด block ก่อนเวลา

Show<T>/Hide<T> ของ UIBlocker นับ reference count ให้อัตโนมัติ — ถ้ามี 2 ระบบเรียก Show พร้อมกัน (เช่น network request + asset load) แล้วอันหนึ่งเสร็จก่อนแล้วเรียก Hide จะไม่หลุด block ปิดจริงก็ต่อเมื่อจำนวนครั้งที่เรียก Hide ครบเท่ากับจำนวนครั้งที่เรียก Show แล้วเท่านั้น — เรียก API เดียวกับ Screen/Popup ได้เลย ไม่ต้องจำ API แยก:

UIManager.Instance.Show<LoadingBlocker>();  // เรียกได้จากหลายที่พร้อมกัน นับให้เอง
UIManager.Instance.Hide<LoadingBlocker>();

คำถามที่พบบ่อย

Show/Spawn แล้ว throw Resources.Load<UIView>(...) returned null

prefab ไม่ได้อยู่ใต้โฟลเดอร์ที่ชื่อ Resources เป๊ะ หรือ path ใน catalog entry ไม่ตรงกับตำแหน่งจริง — เปิด entry นั้นใน catalog, ลาก prefab เข้าช่อง "Drag prefab" ใหม่แล้วกด "Sync" เพื่อ resync path/type string

Rename class หรือย้ายไฟล์ .cs แล้ว catalog หา Type ไม่เจอ

UICatalogEntry เก็บ Type เป็น assembly-qualified string ไม่ใช่ object reference ปกติที่ Unity อัปเดตให้อัตโนมัติ — ต้องกด "Sync" ที่ entry นั้นใหม่ทุกครั้งหลัง rename/ย้าย assembly

Show<T>() สร้าง instance ใหม่ทุกครั้งที่เรียก ไม่ reuse จาก pool

เช็คว่า Type นั้นไม่ได้มี entry ซ้ำสองอันใน catalog (ดู HelpBox เตือนสีเหลืองในหัว Inspector) — ถ้ามี entry ซ้ำ แต่ละครั้งอาจ resolve ไปคนละ pool

อยากเปิดหลาย instance ของ Popup/Screen เดียวกันพร้อมกัน ทำไงดี

Show/Hide<T> รองรับ instance เดียวต่อ Type เท่านั้นโดยตั้งใจ — ถ้าต้องการหลาย instance พร้อมกัน (floating text, damage popup ซ้ำๆ) ให้เปลี่ยนไปสืบทอด UIWidget แล้วใช้ Spawn/Despawn แทน

RecycledScrollView โชว์ cell ว่างๆ ตอนเลื่อนเร็วๆ

เพิ่มค่า Overscan Cells ใน Inspector ของ RecycledScrollView — ค่านี้คือจำนวน cell พิเศษที่ pool ไว้เกินขอบเขต viewport กันโชว์ว่างระหว่างเลื่อนเร็ว

อยากลบตัวอย่าง (Examples/) ทิ้ง จะกระทบ framework ไหม

ไม่กระทบเลย — Examples/ อยู่คนละ assembly (Aexxa.CanvasCore.Examples) จาก framework core (Aexxa.CanvasCore.Runtime/.Editor) โดยตั้งใจ ลบทั้งโฟลเดอร์ได้เลย แล้วสร้าง UICatalogSO/UI ของโปรเจ็คตัวเองแทนตามเริ่มต้นใช้งาน

ต้องการ async load prefab จริงๆ (ไม่ block main thread) ทำได้ไหม

ตอนนี้ยังไม่รองรับ — Resources.Load เป็น synchronous call เสมอ (เกิด hitch สั้นๆ แค่ครั้งแรกต่อ Type ไม่ใช่ทุกครั้งที่ spawn) ถ้าต้องการ async/remote content จริงๆ ต้องอัปเกรดเป็น Addressables เอง — ยังไม่มีใน scope ของแพ็คเกจนี้
